# انتقال اجرای Evren Nexus به هاست

این بسته برای اجرای زمان‌بندی‌شده روی هاست فعلی است و هیچ فایل یا Workflow فعلی را حذف یا غیرفعال نمی‌کند. ابتدا فقط روی یک مسیر آزمایشی اجرا شود؛ تا وقتی خروجی سایت روی هاست بررسی نشده، Cron نهایی را فعال و اجرای GitHub Actions را خاموش نکنید.

## پیش‌نیازهای تأییدشده روی هاست
- Python 3 و Node.js نسخه 20 یا سازگار با اسکریپت‌های پروژه
- نصب وابستگی Node یعنی `cheerio@1.0.0-rc.12` در ریشه checkout پروژه
- دسترسی نوشتن به فایل‌های checkout و document root سایت
- ابزار `flock` برای جلوگیری از اجرای هم‌زمان Cronها

## راه‌اندازی
1. مخزن را در مسیری خارج از `public_html` قرار دهید؛ نمونه: `/home/USERNAME/evrenexus`. فایل‌های مخزن و داده‌های قابل‌تغییر باید در همین مسیر باقی بمانند.
2. در ریشه checkout، وابستگی موجود در Workflow را یک‌بار نصب کنید: `npm install --no-save cheerio@1.0.0-rc.12`. نصب را داخل Cron تکرار نکنید.
3. فایل تنظیمات خصوصی بسازید: `$HOME/.config/evrenexus/host.env` و مقدار واقعی document root را قرار دهید:
   `EVRENEXUS_WEBROOT=/home/USERNAME/public_html`
   مسیر نمونه است؛ مقدار واقعی هاست خودتان را بگذارید. این فایل نباید وارد Git شود.
4. قبل از Cron، از داخل checkout اجرا کنید:
   `bash hosting/run-update.sh news`
   سپس صفحه اصلی، صفحه خبرها، آرشیو، داده‌های قیمت و لاگ `$HOME/logs/evrenexus-update.log` را بررسی کنید.
5. پس از تأیید، زمان‌بندی‌های `crontab.example` را با مسیر واقعی checkout و کاربر هاست جایگزین کنید.

## چه کار می‌کند؟
- `news`: آزمون طبقه‌بندی، جمع‌آوری خبر (مگر اینکه اتوماسیون pause شده باشد)، دریافت TGJU/Nobitex، ساخت و اعتبارسنجی فید آخرین خبرها و تلاش برای ساخت داده‌های عمومی و فهرست‌های مطالب.
- `crypto`: به‌روزرسانی داده LBank.
- `cars`: به‌روزرسانی قیمت خودرو.
- بعد از اجرای موفق مرحله اجباری هر حالت، فایل‌های سایت را به document root کپی می‌کند.
- یک قفل مشترک از تداخل اجراها جلوگیری می‌کند؛ فایل‌های مقصد که در checkout وجود ندارند عمداً حذف نمی‌شوند.

## محدودیت مهم
این بسته اجرای محلی و کپی فایل‌ها را آماده می‌کند؛ خودش به پنل Serverha وصل نمی‌شود و Cron را از راه دور ثبت نمی‌کند. مرحله AI (`scripts/news_ai.py`) عمداً به‌صورت خودکار اجرا نمی‌شود، چون باید کلیدهای سرویس در متغیرهای محیطی خصوصی هاست پیکربندی و مسیر خروجی آن جداگانه آزمایش شود. در مرحله اول، GitHub Actions همچنان فعال می‌ماند تا از انتشار ناقص یا دو منبع متناقض جلوگیری شود.
